
# Insight Engine ETL

The Insight Engine ETL source code repository contains Python scripts for extracting, transforming, and loading (ETL) raw data from various sources into the Insight Engine Postgres database. The goal is to convert diverse data into a time series format for analysis.

## Data Extraction

The ETL scripts are designed to handle multiple data extraction methods, from a variety of external sources, including:
  * Scraping websites
  * Downloading CSV/Excel/JSON files
  * Calling APIs
  * Reading emails
  * Fetching data from FTP servers or S3 buckets

This versatility ensures that data from a wide range of sources can be seamlessly integrated into the Insight Engine. The extracted data is initially stored in its raw format, preserving its original structure and content. It is then convert into standard CSV templates for loading into IE.

Over time we will accumulate an archive of the raw data as it existed at different points in time, independent of IE CSV formats. This can be especially valuable with sources like BLS, where they only make the most recent version of the data available to download.

## Data Transformation

The raw data is then transformed into standardized CSV files suitable for the Insight Engine. This involves data cleaning, normalization, and reformatting. The scripts are modular, with each transformation step represented as a task in Airflow DAGs, providing clear workflow visibility.

## Data Loading

Transformed data is uploaded to an AWS S3 bucket and then loaded into the Postgres database. The ETL scripts create files for source collections, series metadata, and observations according to Insight Engine standards.

## Workflow Management

Apache Airflow schedules and executes the ETL scripts through Directed Acyclic Graphs (DAGs). Each data source has its own DAG for incremental data loading. Airflow ensures efficient task scheduling, dependency management, and error handling.

### Benefits

  * **Modular Code**: Enhances maintainability and clarity.
  * **Re-runnable Tasks**: Allows re-running parts of the workflow without re-extracting data.
  * **Data Archiving**: Builds an archive of raw data over time, preserving historical versions.
